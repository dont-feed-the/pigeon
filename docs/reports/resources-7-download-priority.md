# Protection before optional kept-folder downloads

Native protection and optional kept-folder get children previously shared
one Transfer class. Between keys, kept downloads now use a scoped repository view that
maps transfer admission to Download, below protection and above routine
scrub. The original repository and its clones retain their policy, and the
Git view shares the original purge/mutation fence. Native argv, authority,
framing, disk reserve and process-group cancellation stay unchanged.

Active keys retain their native transfer policy until completion: pausing a
key for another protection child could hold an annex object lock that the
higher work itself needs. A separate starting permission gates both
one-shot exec and the next batch stdin key. Capture and environmental
pauses still govern active keys.

Deadline charging retains the actual Transfer identity so the group's own
content-shaper waits remain excluded. Metadata is outside heavy admission.
Capture, power, metered and disk policies still apply. A designated repair
continues sharing protection priority rather than routine scrub priority.

This covers the queued kept-folder worker and direct keep retrieval. Other
interactive restore/install paths retain conservative transfer priority;
the complete global six-class queue and native resource budgets remain
open. Validation is recorded after execution.
